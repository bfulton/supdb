## Where it stands

- Five rules applied across the slices change **35 rows**: 21 inline rows
  become test-seams (R1), 4 deletions become keeps (R2), 3 keep-stable rows
  become test-seams (R3), 6 inline rows become keeps (R4), and one test-seam
  goes with the branch it tests (R5). Three more checks found the slices
  consistent and change nothing (R6-R8).
- After them: 267 options removed (156 inline, 103 delete-refuted, 8
  delete-unread), 95 keep-experimental, 63 test-seam, 28 keep-stable; 431 of
  the 643 supdb arms deleted, no roster arm among them.
- The 120-odd cluster names the five agents chose map to **69 unified
  clusters** (66 with something to remove), landed as **29 removal pull
  requests and one API pull request**, each under about 1,500 changed lines
  by the estimate below.
- First three: **PR1** adaptive-lag, upkeep-wake, seal-shape, fit-trim,
  zpages-drop (12 options, 14 arms, ~840 lines); **PR2** zpages-build,
  zpages-crossing, stride, upkeep-yield, scan-merge (10 options, 18 arms,
  ~1,120); **PR3** scan-ahead, copies (14 options, 26 arms, ~1,310).
- Two things to decide before phase 1 starts, outside the ledger: decision
  1's `#[non_exhaustive]` on `Options` breaks the 667 `Options { .. }`
  literals in tests/, bench/ and examples (functional update is refused for a
  non-exhaustive struct from another crate), so it cannot be a one-line
  change; and every removal of a fuzz-drawn option shifts the draws after it
  (rule F below).

## Part 2: the order of phase 1

### Unified clusters

Every row's slice cluster maps to one of 69 unified clusters
(`clusters.csv`, columns struct, name, cluster, pr). The mapping merges the
names the agents coined for one family (`zpages-walk` and
`zpages-scan-walk`; `zpages-seam` and `zpages-seams`; `copy-walk`,
`copy-prefetch`, `wide-copy` and `copies`; `scan-prefetch`, `scan-levers`,
`scan-raw-ahead` and `scan-seek`; `forms-fit` and `zpages-fit-trim`;
`scan-snapshot` and `seal-snapshot`; and so on, the "from" column), moves
`same_blocks_from_index` into `merge-drop` and `fail_open_alt_removal` into
`manifest` (they share an arm or a branch with them), and splits the six
families too large for one reviewed commit (`point-read`, `zpages-coding`
with the recode policies, `settle`, `memory`, `direct-table`, `snapshot`).
Three clusters hold only kept rows and get no pull request: `kept-core` (the
caller's knobs: sync, encryption, sizes, read advice, the blob reader's
switches, `upkeep`, `scan_timers`, `publish_in_background`, `one_file`,
`zpages`, `zpages_under_cipher`), `open-seams` and `zpages-seams`.

"Removes" is the option, its other branch and its arms. "Arm-only" is a
test-seam whose arms and Policy pins go while the field stays hidden.
"Depends on" names the three kinds the task asked for: an option read only
inside another's branch, a shared Policy field, a shared arm. Five arms are
named by two clusters, which is what puts those pairs in one pull request or
in order: `supdb-zmemoplain` (zpages-read, zpages-walk),
`supdb-zpromotestarts` (promote, zpages-scan-seek),
`supdb-cache64tofitzpageshot8dropsettleevery` (zpages-recode,
settle-filing), `supdb-nocopiesfitchain` (block-cache, merge-chain) and
`supdb-rebasedropsshed` (forms-carry, settle-filing); `supdb-zreparse` is a
sixth by the notes (zpages-recode, zpages-codec).

Size is read sites in src/ (non-test) / arms deleted / test functions that
set a removed option, and an estimate of changed lines: the removed fields'
rustdoc, about 6 lines a read site, about 28 an arm (its `open` entry, its
constructor, its name in the naming function and its rows in the engines.rs
arm tables, which run about 11 lines an arm in
`the_memory_arms_differ_from_supdb_in_their_option_alone` and 21 in
`the_raw_cache_arm_differs...`), a third of the lines of the test functions
that set the removed shape, and the DESIGN.md catalogue lines. It is a
relative scale, not a diff: a branch that is a whole code path (the rename
manifest, the probe merge path) is larger than six lines a read.

### What every pull request carries

- **The engines.rs arm tables.** Nearly every deleted arm has rows in one
  of 26 test functions of `bench/src/engines.rs`
  (`the_memory_arms_differ_from_supdb_in_their_option_alone` holds 189 arms),
  plus its `open` entry, its constructor and its line in the naming
  function. These tables are the one file every pull request edits, so the
  pull requests are sequential, never parallel.
- **The lists that only go down.** A removed public seam of `Db` or `Reader`
  is a line of `tests/data/cost-entries.txt` lowered in the same commit; a
  removed branch that held a counted token lowers `tests/data/couplings.txt`
  (`SUPDB_WALL_PRINT=1` prints the measured table; the cluster table's
  "couplings.txt: check" counts the scopes that hold both a removed read and
  a counted token). `scripts/raises.txt` lines that name removed options are
  spent and may be dropped.
- **The cost gate.** `scripts/cost.sh` refuses to count when the suite's
  `supdb_get`, `supdb_range` or the Supdb `get`, `range`, `write_batch`
  differ between sides; no cluster needs to touch them, and a commit that
  does is wrong. A removed branch can still move the compiler's inlining and
  read as a gain in a neighbour: read it by instruction before calling it
  the removal's (CLAUDE.md's rule for counts that moved with the source
  unchanged).
- **Rule F, the fuzz's draws.** `tests/fuzz.rs`'s `pick_cfg` draws its
  ZFUZZ_OPTVARY choices from a side stream in a fixed order, and some
  options (`promote_entries`, `zpages_promote_copies`) from the main one. A
  draw deleted shifts every draw after it, so every seed runs other cases
  from that commit on and a failure that appears is not yet the commit's.
  Keep the call and discard its value (`let _ = side.chance(25);`) in the
  removing commit; one commit at the end of phase 1 may renumber.
- **DESIGN.md and the rustdoc.** Each deleted arm's catalogue line in
  `bench/DESIGN.md` goes with it (R6). The rustdoc of kept options names
  deleted arms in about 470 places in `src/db.rs`; those are phase 5's
  words, except where a kept option's doc says "X is the arm" for an arm the
  commit deletes.
