WAVE 2 BRIEF: STAGE 2a, THE PROOF SLICE (read it completely; it binds you).

THE PROJECT. supdb (/home/user/supdb) is a read-optimized embedded key-multivalue store; bench/ is its suite against LMDB and RocksDB. The user's aim: beat both everywhere except disk space, and "every loss should be reversible": a cell a comparator wins is a workload the engine has no strategy for (CLAUDE.md, "The suite lives in bench/", third consequence). Read /home/user/supdb/CLAUDE.md and /home/user/supdb/bench/CLAUDE.md first (the same files are in your worktree): they are the rules, and the failure shapes in CLAUDE.md are real, each cost a gate cycle.

WHAT IS KNOWN (measured on this host, a Firecracker guest with 4 vCPUs, under a 1 GiB cgroup memory bound at 10M keys; docs/engine.md "Out of core" has the tables):
- Against LMDB with readahead off our point reads run 0.68x (54k vs 79-82k/s) with 0.41-0.46 faults a read against 0.27, because our file is bigger: a 190 MB hash region every read touches (resident) plus 1.3 GB of records in a cache of 0.94 GB.
- A standalone probe (bench/examples/zprobe, prereg.md) shows the records packed into LZ4 groups that each fill one 4 KiB page (68 B a key, 0.68 GB at 10M keys) take 0.000 faults a read once resident and run 262-280k reads/s, up to about 96% of the cache; the engine's own byte layout packs 58 records a page (bench/examples/zsize.rs).
- The design is /tmp/claude-0/-home-user-supdb/43547e2e-b745-59c0-b3a0-b32f7c7e7919/scratchpad/design/zpages.md (a pre-registered, three-times-reviewed design). Read sections 0, 1.5, 2 (all), 3.1-3.3 and 3.8-3.9, 5.1-5.5 and 5.7, 6.1-6.4, 7.3 and the stage 2a row of section 8. Where the code and the design disagree, the code is right: say so with file:line and do the right thing.
- Wave 1 is merged into your base: src/db/zpages.rs is the layout half (page encode and decode, fill_group, the fence, the trailer, bind32, verify_page; 4,000 lines with their tests and wired to nothing), src/db/zselect.rs the selector's core (wired to nothing: do not touch it), flatindex::record_key_next, Options::point_via_ord and the arm supdb-nocacheordread (off by default). YOUR TASK, the forced arm for point reads and counts only (design section 8, stage 2a). Deliver, on a branch named wave2-zproof cut from the base the parent names:
1. The option. pub enum ZPages { Off, Always } (Auto is stage 4a; add only what this stage uses), Default Off, beside ReadAdvice and re-exported at the crate root with the rest of the native-only list; Options::zpages. check_options refuses Always with writer_pins off (the cell is freed through the epoch). The default behaviour must not change by a single instruction on the read path that matters beyond one load and one not-taken branch; say what that costs in instructions a point read (callgrind, 100k keys, release, as the ordread track did: /tmp/claude-0/-home-user-supdb/43547e2e-b745-59c0-b3a0-b32f7c7e7919/scratchpad/wave1/ordread-fix/inline-probe-results.txt).
2. The sidecar. A derived file zpg-<id>-<end_seq>.zpg per partition (2.1), built from the partition's own bytes by a ZBuild (2.6) that streams the records through the directory (never the difference of two directory words), fills groups with fill_group chained from the previous page's count, verifies every page it writes with the reader's own verify_page, writes through plain pieces with start_writeback and the trailer last, renames from a temp name, unsynced. 2a declines (counted, no file) a partition with a block-backed, oversize or incompressible record and one under the size floor, and builds no filter (the trailer says so: the filter flag clear); absent keys therefore cost a page in this stage, which is correct and slower, and is stated in the report. Bound to its segment by content (2.5): at attach the trailer must equal what the live segment recomputes (Blob::z_source_facts and Blob::record_regions, the two new accessors, native-only), bind32 recomputed, the key section's checksum row CRC among them; the fence tiled from the resident part alone; the first, the last and fourteen evenly spaced pages' CRCs checked. Anything that fails is counted and the raw form serves.
3. The read. ZSide per 2.4 (map, fence, verified and bad bitmaps, damaged, id, ident), ZCell on Seg (an AtomicPtr installed once, never cleared in this stage, freed with the Seg), the gate loaded once per read beside the state, Reader::read_all and Reader::count for the partition source by ZSide::read_all / count (3.2, 3.3; callback-shaped, scratch from a thread-local Cell taken out and put back so a re-entrant callback is safe, decode with lz4_flex::block::decompress_into checking the returned length against ulen, the first-decode checks of 2.7 and the verified bit). A page that fails any check is read from the raw form and counted, never answered absent. Everything else (the pieces, the frozen tables, the live table, the tombstone pre-pass, the order sources are read in) is untouched; scans of a covered partition stay raw in this stage and are counted raw_scans (3.10).
4. The build trigger of the forced arm: a #[doc(hidden)] pub hook Db::zpages_settle() that builds, attaches and installs a sidecar for every live partition that lacks one, and waits for it; Supdb::sync in the suite calls it after flush under the arm (s15 of 6.2) so the arm cannot silently measure the raw form. Build on the calling thread or on a thread you join; no controller, no warm, no memo, no filter, no SegBlob, no retirement beyond Seg's own drop, no promotion or merge handling beyond: a Seg that replaces another starts with an empty cell and its reads are raw and counted (rawserves). A store reopened over existing sidecars attaches them at open if that is a few lines, else it does not and says so.
5. Counters (6.4, only those this stage has): reads, rawserves, builds, build failures, declines by reason, rejected_damage, rejected_identity, raw_scans, plus gauges; per-slot counters on the handle's own line if they are written on the read path (CLAUDE.md "A slot table whose slots share a line"), never a shared word a reader bumps.
6. The suite arm supdb-nocachezpages = the nocache policy with ZPages::Always, mirrored at every site of 6.2 (s1-s15) it needs, with the test that the arm differs from its default in the option alone, the one_pass refusal of a forced arm whose sidecars are not whole (after the load: sidecars at the end == partitions; after the read phase: reads > 0 for Always, == 0 for Off), counters printed by bench ab, and nothing added to the rosters (the arm is chosen by hand with --arms).
7. Tests, all under profile.checked, in tests/zpages.rs (its own file and process; fixtures copied) and unit tests where they belong: the oracle (a model-checked mixed workload, puts, multi-value keys, deletes, seals, merges, promotions, reopen; every read and count through the writer and through handles equals the model and equals an Off store fed the same operations, and the test asserts the z path was taken: reads > 0 for Always, == 0 for Off); absent keys (below the first, above the last, between two records, one byte either side of fence keys, a proper prefix of a fence key, a key longer than a fence key it extends); runs of every shape (1, 2, 17, 200, 1500 values, FIXED and prefixed, zero-length values, tombstone-only keys); a direct-run segment with commit markers inside its record region; damage (every seventh byte of the page region flipped, one at a time, in a copy: each read still answers right through the raw form and is counted, the page's bad bit set, never a wrong answer or a panic; every field of the trailer wrong in turn: attach refuses and counts); identity (a sidecar copied to another segment's name, one whose segment was rewritten under the same id and end_seq: refused); a misaligned STORED buffer is refused and counted, never answered absent. Every test must fail when the thing it guards is broken: break it and see (the layout track's reviewer broke its tests mutation by mutation and found five that did not fail).
