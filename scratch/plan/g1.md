## What every unit inherits

- The process: failing test or red input first and shown red; the change;
  mutants of the change against its tests; two reviews (cipher and crash;
  what a store in the clear pays); commit after `sh scripts/check.sh build
  test lint` is green.
- No instruction added per key, entry, block or step for a store in the
  clear, counted with callgrind by function against the commit before, over
  the rows of forms.md §5 named in the unit:
  1 `read_only.rs supdb 100000 1 n-none`; 2 `lag0_probe.rs supdb 100000 1`
  at a limit under and over `SCAN_REST` (1024); 3 rows 1 and 2 with
  `supdb-nocachezpages`; 4 `merge_walk.rs 100000 4 1`; 5 `work_probe.rs
  100000 whole`; 6 `load_only.rs supdb 100000 1`; 7 a seal probe
  (`SegmentWriter::create_with`); 8 `Blob::scan_at` through the public API.
  Rows 7 and 8 exist from G1-3 on; before it, the units that need them are
  ordered after it.
- No feature switched off, refused or limited under a cipher to make a unit
  easier.
- A gate test is trusted only after it has failed on a known-red input.
- Nothing is exempt from the format gate; everything holds to `-D warnings`.
- A unit that changes a public signature of `Bytes`, `Blob` or `MmapBytes`
  also runs `sh scripts/check.sh wasm` (wasmapi.rs implements `Bytes` for
  `VecBytes` and `HostBytes`) and `sh scripts/check.sh bench` (bench/src
  names `Blob<MmapBytes>` and `MmapBytes::open`, engines.rs:9445-9641). The
  commit gate runs neither.

## Order and why

1. G1-1 wall, G1-2 door, G1-3 cost: the gate tests at today's counts. They
   change no instruction of any build.
2. G1-4, G1-5, G1-6: the rewrites of code that answers wrong or does nothing
   for a source that lends by the piece, each with a test that shows the
   wrong answer today. None changes a default path of a store in the clear;
   G1-6 is the one with a plain-store risk, which it must show level.
3. G1-7: the visibility changes that make a whole borrow uncompilable,
   after the callers that needed one are gone.
4. G1-8: the CLAUDE.md and docs amendments the contract changes owe, last,
   so they describe what landed.

The source checks of G1-1, G1-2, G1-3 (and later G2's) live in one test
binary, `tests/source.rs`, sharing one lexer. One binary keeps the lexer's
compile cost once and its unit tests in one place.

- **Stage:** G1. **Engine behaviour change:** yes, under a cipher only, and
  only on paths no default reaches (below).
- **What it changes** (borrows notes §2 items 1-2, §1.4; borrows check §2.C):

    the section whole") is corrected: the code answers 0 for
    `Index::Sparse` alone (borrows notes §2).

- **Who reaches the change under a cipher.** `willneed_*` only where

- **Depends on:** G1-3 (rows).

## Unit G1-5 `authenticated`: a checksum skipped only where the source checks what it lends

- **Stage:** G1. **Engine behaviour change:** no for any store; yes for an
  outside `Bytes` that lends by the piece and checks nothing.
- **Why this shape and not forms.md's.** The two skips are deliberate
  (blob.rs:975-979, ordindex.rs:406-413): under a cipher the pager's tag
  covers every chunk, and checking at open would ask for the whole ordered
  index and the whole key section at every open. That breaks the cipher
  open bound tests/cipher.rs:477-493 holds (`c.fills <= 6 * files`) and
  1705-1716, 1764 for form files (borrows check §1.3). They are wrong only
  for a piecewise source with no check of its own: the public test source
  `Piecewise`, or an outside caller's. The ordered index is opened only
  through `vault::map` (ordindex.rs:404), whose sources are a mapped file
  (checked) or a paged mapping (authenticated), so its skip is right for
  every source it can meet and is left alone.
- **What it changes.**
  - `Bytes` gains `fn authenticated(&self) -> bool { false }`, defaulted so
    the 11 outside impls compile (borrows check §0); `MmapBytes` answers
    `true` for `Own::Paged`.
  - `Blob::open_with`'s row check (blob.rs:980) is skipped where the
    section is held by the piece **and** the source is authenticated; a
    piece source that is not authenticated has its row verified through
    `Pieces` at open (each piece asked once; it is not a cipher store, so
    the open bound does not apply).
- **Red test** (borrows notes §4 step 3(b), borrows check §1.4): in
  `tests/blob.rs`, a segment with one byte of its key section flipped and its
  block CRCs left whole, opened over `Piecewise`: must fail at open. Today it
  opens. The guard: tests/cipher.rs's open-bound test stays green, and is
  run in the unit's own run of the commit gate (it is in the test group).
- **Mutants.** `authenticated` true by default; the skip still on
  `piecewise` alone; the verify through `Pieces` asking for the section
  whole; `MmapBytes` answering `true` for a mapped file.
- **Callgrind rows.** 6 (open) and 8; the check is at open, not per key.
  At risk: `Blob::open_with` only.
- **Must not.** Verify the cipher store's sections at open. Touch
  `OrdIndex::open`'s skip.
- **Leaves.** Wall token: `authenticated` is a byte-source property in the
  seam (bytes.rs), named from blob.rs; G1-1's file is lowered by the

- **Depends on:** G1-1 (the wall counts move), G1-3.

## Changes to the contract (forms.md) that G1 makes

1. **R2's visibility does not exist in Rust.** A trait method cannot carry
   `pub(in crate::bytes)`, and `pub(in path)` reaches only ancestors. G1-7
   seals `lend_at` and `Paging::base` with a token whose constructor is
   confined by `pub(in crate::blob)` or `pub(in crate::bytes)`, and replaces
   the accessor pairs with an enum. Lost: whole-range `slice_at` stays a
   whole borrow and compiles; it is held at run time by G2 only.
2. **R2's silent no-ops are a different list.** The ordered index's CRC
   skip and the key section's row skip are right under a cipher (the tag
   covers every chunk) and a test holds the open bound that verifying would
   break. G1-5 makes the row skip depend on the source authenticating,
   which fixes it for an outside piece source; the ordered index's skip is
   left. "The zero footprint" is no longer in the code. Added:
   `record_offset`, `resident_pages`.
3. **R3 at G1 removes the address, not the descriptor.** Advice by
   descriptor stays at the sites that hold a door handle until S1's typed
   handles (forms.md §4 §2 puts it there). Keeping a descriptor per mapping
   was rejected for its unpriced descriptor cost. The span residency method
   replaces three, it does not add a fourth.
4. **G-door is a separate clippy run over the library.** A config in
   `scripts/door`, `--lib`, `--profile checked`, Linux only, explicit paths.
   The allowlist adds `crypt.rs`, `dirkey.rs` and `blocks.rs`, and 24 item
   allows stand at G1. A source test stays for what clippy cannot hold
   (where an allow stands, `extern "C"`, `/proc` literals), against
   forms.md's "this replaces today's text test". Tests and examples are not
   linted by the door: they read stored files by path on purpose.
5. **G-wall's keys and lists.** `Kind` is private and held by the compiler;
   `bytes.rs` is counted as the seam; `vault::real` is counted; the S3*
   lines fall at S6 (decisions.md order item 10); S4's lines are
   conditional. The gate compares totals by (file, token, region) unless
   question 2 is answered otherwise.
6. **The thread half of G-door** waits for S1 unless question 1 says
   otherwise; G1 holds it by a per-file count.
