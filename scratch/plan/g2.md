## G2 is split in two

- **G2a, on today's vault and pager.** Tier 1 (every test that opens a plain
  store, run as a store under an identity cipher with forced eviction and
  the guard), the fuzz half of tier 2, the poison draw, the injected-budget
  subset through `ZInject`, the asks ratchet (R15), advice parity (R3's
  gate) and G-options (R13). What it holds: the read contract on the paths
  tests reach -- borrows by asking, pins, rests, the door through the decoy
  directory, the debug pin assertion in `Paged::ensure`. design.md §6 lists
  each of those as staying through S3, so G2a keeps working when the page
  layer replaces the envelope arm.
- **G2b, after the page layer (S3).** A cache of a few pages exactly; a
  guard exact to the chunk; the crash-state API (discard since sync, tear)
  that brings the byte-level crash tests into the pass. Each needs what
  today's pager does not have: eviction by the page and 4096-byte chunks
  (today a unit is 256 chunks of 4080 bytes, pager.rs:108-125, with 4-6 MiB
  of slack before a wait, pager.rs:319-321; the smallest working budget in
  use is the fuzz's 16 KiB). G2b's units are listed at the end, not planned
  in detail: their code depends on S2-S3's interfaces.

## Unit G2-1 `nopin`: an unpinned writer is refused under a cipher

- **Stage:** G2a. **Engine behaviour change:** yes, a refusal at open.
- **Why first.** It is an engine finding the scouting made, not a conform
  hook (conform check §4a): `check_options` accepts `writer_pins: false`
  with `Encryption::Cipher`. The writer's reads then take no slot
  (`pin_slot.filter(|_| self.opts.writer_pins)`, db.rs:18934, 19006, 19109),
  so the evictor does not wait for them: unsound in release, a debug
  assertion in `Paged::ensure` (pager.rs:1316-1320) in checked builds. Two
  tests the conform pass would run set it (tests/db.rs:1005,
  tests/zpages.rs:6034).
- **What it changes.** `check_options` (db.rs:12272) refuses `writer_pins`
  off where `opts.encryption` is `Cipher`, worded as its siblings are (what
  the combination cannot do soundly). This is the store's existing rule for
  an unpinned writer -- sound only while nothing else frees what it reads --
  applied to the evictor, which frees what it reads. It is not a feature
  limited under a cipher: `writer_pins: false` is a pricing arm
  (`supdb-nopin`), unsound there.
- **Red test.** tests/cipher.rs: a store created with `writer_pins: false`,
  `publish_in_background: false`, `snapshot_keeper: false` and a cipher is
  refused with the words, and its directory is left as it was (CLAUDE.md:
  a refusal is tested by what it says). Today it opens. A second test, run
  only under debug assertions, that today's open followed by a read of a
  sealed segment panics in `ensure`, to show the red is the soundness and
  not the wording: optional, since it needs a cache small enough to evict.
- **Mutants.** The refusal checking `Kernel` instead of `Cipher`; placed
  after `create_dir_all`; the words not naming `writer_pins`.
- **Callgrind rows.** 6 (open). Not per key.
- **Must not.** Make the writer pin under a cipher regardless of the option
  (an option resolved by mode outside the layer, forms.md R12).
- **Depends on:** G1 landed.

## Unit G2-2 `resolve`: a plain store becomes a store under an identity cipher when asked

- **Stage:** G2a. **Engine behaviour change:** none in release; in checked
  builds only under `SUPDB_CONFORM=1`.
- **What it changes** (conform notes §1-§2, conform check §4b):
  - `src/db/vault.rs` gains, under `#[cfg(debug_assertions)]`:
    - an identity `Aead` (crypt.rs:141-151): `encrypt` leaves the buffer and
      returns a tag that depends on the nonce, the associated data and the
      buffer (a CRC32C of the three widened to 16 bytes), `decrypt` compares
      it. A constant tag would let a chunk from the wrong place pass;
    - a reserved key id (the notes suggest `u64::MAX - 0xC0F`);
    - `vault::resolve(dir, &mut opts, creating) -> Encryption` (new; no such
      function exists), called at the head of both match arms
      (db.rs:28356 `Db::create`, db.rs:28691 `Db::open`). At create it
      substitutes `Encryption::None` when conform is on and the creating
      thread has not opted out; at open only where the marker's key id is
      the conform id (`vault::key_id`, vault.rs:397), so a store built plain
      by hand, or under a real cipher, opens as it was built
      (tests/cipher.rs:250-268). `Kernel` and `Cipher` are left alone.
    - For a conform store `cipher_controller` is not applied: the store runs
      `ZPages::Auto` as the test asked, not `Off`.
  - In release, `conform_on()` is a `const fn` returning `false`, the shape
    of `pager::guard_on` (pager.rs:1569-1578); the match arms compile to
    what they are today.
  - The test-facing API exists in release as a no-op stub, `#[doc(hidden)]`
    (`supdb::conform::{active, plain_files_only}`), because the lint group
    builds the tests in release (conform check §4b). `plain_files_only(reason)`
    returns an RAII guard that sets a thread-local read at `Db::create`
    and resets at drop.
- **Red test.** `conform_makes_a_plain_store_one_under_a_cipher` in
  tests/db.rs: with `supdb::conform::active()` it asserts
  `db.cipher_counts().is_some()` on a store created with `Encryption::None`;
  without, `is_none()`. Under `SUPDB_CONFORM=1` it fails today (nothing
  substitutes). Plus a vault unit test that the identity `Aead` refuses a
  chunk under another nonce, another associated datum and a changed byte.
- **Mutants.** Substitution at open regardless of the key id; the opt-out
  ignored; `cipher_controller` still applied; a constant tag; the release
  stub doing work.
- **Callgrind rows.** None move: every probe builds in release, where the
  substitution is compiled out. The checked profile pays one `OnceLock`
  load per create or open and a thread-local load per create.
- **Must not.** Touch the release open path; resolve any option by mode
  other than the controller's (which exists today and goes at S5).
- **Depends on:** G2-1.

- **Stage:** G2a. **Engine behaviour change:** none in release; in checked

    (db.rs:10737-10745) and `pager::Hold::rest` (pager.rs:178-184) ask the

    its first chunk's fill, so the guard is exact only at G2b.
  - Reached only where `shared.pager` is `Some`, so a plain store pays

- **Red input.** A mutant of `merge_ranks` (db.rs, the step loop) that keeps

- **Callgrind rows.** None in release. Note in the commit the checked-profile

- **Must not.** Wait at a rest. Evict a file with no envelope yet (it cannot

## G2b, after the page layer (not planned in detail)

- `G2b-cache`: tier 2's cache of a few pages exactly, once eviction is by
  the page (S3).
- `G2b-guard`: `PROT_NONE` until a chunk is filled, exact once a chunk is a
  page (S3's 4096-byte chunks).
- `G2b-crash`: a layer test API that builds crash states (discard since

- `G2b-classes`: the conform store mirrors the class contracts of S2 in its

## Changes to the contract (forms.md) that G2 makes

1. **No cache of 4 pages on today's pager.** It gives back units of 256
   chunks with megabytes of slack; 16 KiB is the working minimum. Tier 2
   runs at 16 KiB; the exact small cache is G2b.
2. **The guard is not exact on today's pager.** 4080-byte chunks share
   pages; G2-6's guard makes a page readable from its first chunk's fill.
3. **Eviction at a rest is asked, not done.** A rest that waited for a
   pass would wait for every pinned reader. What it catches depends on the
   evictor's pass landing between the rest and the reuse.
4. **Files with no envelope are never given back**, so a borrow kept
   across a rest into a seal's output, a merge's piece or a run's file is
   invisible to the pass until the page layer.
5. **The opt-outs are 267 plain tests plus 81 cipher tests plus the mode
   seams**, not forms.md's estimate; the crash-state API is G2b, so conform
   holds no crash window under the paged path until then.
6. **The opt-out API exists in release** as a no-op stub, because the lint
   group builds the tests in release.
7. **`vault::resolve` is new**, and the substitution skips
   `cipher_controller` for a conform store.
8. **Engine fix found on the way**: an unpinned writer under a cipher is
   refused (G2-1).
