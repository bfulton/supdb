# Functions a store in the clear runs per key, entry, block or step: a gain
# in any of them is a cost every operation pays (scripts/cost.sh). A line is
# a path in the form scripts/cost-diff.py reduces callgrind's names to --
# generic arguments dropped and an impl's `<T>::f` or `<T as Tr>::f` read as
# `T::f`, so `<supdb::blob::Blob<supdb::bytes::MmapBytes>>::scan_at_in::<F>`
# is `supdb::blob::Blob::scan_at_in` -- and matches that function, its
# closures and its monomorphs, or, ending in `::`, every function of the
# module or type it names; a line that begins with `!` takes what it matches
# back out, and one that begins with `~` holds it to a bound of its own (the
# section below says how). A probe whose functions no line matches fails; a
# line no probe of a whole run reached (a function inlined everywhere today,
# or gone) is named at the end of the run.
#
# The list is not what the gate holds, only the least of it. In a probe
# with a toggle (the reads, the scans, the commits, the segment work on the
# writer's thread, the seal, Blob::scan_at) every function built from
# source that the toggle collected is hot, at 64 instructions over the
# probe's whole run; in a probe with none (the loads, the writer's round,
# the merge) every function of the engine is hot, at a hundredth of an
# instruction an operation, and so is every line below that names a
# function outside it. What those last cannot see, as a number: 1,000
# instructions over the loads' 100,000 keys, 3,000 over the round's 300,000
# operations, 2,000 over the merge's 200,000, and a `~` line's function its
# bound; and nothing of libc's or a library's code, whose counts follow the
# threads' timing there. The commit probes and `land` count the loads' and
# the segment work's own steps under a toggle, so that a cost of a few
# instructions a commit, a piece or a landing is red there.
# The lines name the per-key, per-entry, per-block and per-step functions
# so that the run says which of them no probe reached.
#
